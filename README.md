# Тахи — каталог фотонаблюдений

Локальный сервис для автоматического определения вида по фотографии и поиска наиболее похожей записи в каталоге известных особей.

## Запуск

Нужен Node.js 20 или новее. Для режима с обучаемой моделью также нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
npm start
```

Откройте http://127.0.0.1:3000. Для другого порта: `PORT=4000 npm start`.

Чтобы подключить модель распознавания животных (первый запуск скачает веса около 204 МБ):

```bash
npm run ml:setup
npm start
```

Уже установленное локальное окружение и веса используются без сетевого доступа при поиске.

Для автоматических рамок и проверки наличия лошади один раз скачайте веса YOLO26x командой `npm run ml:detector-setup`. Если детектор не нашёл лошадь, сервис покажет «Лошадь не обнаружена». На групповом снимке нажмите на рамку или номер лошади. Подтверждение сохраняет выбранный фрагмент. Дальние или перекрытые животные могут остаться без рамки.

## Поделиться с друзьями через интернет

На компьютере, где находятся модель и каталог, установите `cloudflared` и откройте [start-share.command](start-share.command) двойным щелчком в Finder. Команда запускается в обычном Terminal, где должен работать DNS. Также можно выполнить в Terminal:

```bash
npm run share
```

Команда поднимает локальный сервер с паролем и временный Cloudflare Tunnel. **Ссылка, логин `takhi` и случайный пароль выводятся только после подключения туннеля.** Передайте друзьям все три значения. Они смогут загружать фотографии для распознавания и просматривать каталог; менять или удалять записи каталога в общем режиме нельзя. Держите терминал и компьютер включёнными, пока нужен доступ. `Ctrl+C` завершает общий доступ. При новом запуске ссылка и пароль меняются.

В этом режиме фотографии проходят через Cloudflare к вашему компьютеру. Каталог и его снимки хранятся локально в `data/`. Для работы туннеля нужны доступ в интернет и исправный DNS на компьютере с сервисом. Если туннель не подключится, команда не выдаст ссылку для друзей. В ограниченной сетевой среде Codex туннель может не подключиться; тогда запускайте команду из обычного Terminal.

## Работа с сервисом

1. Откройте страницу и выберите фотографию или перетащите её в область загрузки. Распознавание начнётся автоматически.
2. Сервис покажет определённый вид. Если вид — лошадь Пржевальского и каталог заполнен, он также покажет ближайшую запись и её опорный снимок.
3. Если каталог пуст, добавьте известную особь с именем или полевым номером и опорным снимком. Затем добавляйте другие ракурсы через карточку каталога. После изменения каталога выбранное фото анализируется повторно.

Данные сохраняются в `data/horses.json`, фотографии — в `data/images/`. Эта папка исключена из Git. Удаление записи удаляет и её фотографии.

В локальном режиме нажмите «Подтвердить особь» под результатом или откройте «Выбрать другую особь» и сохраните исправление. Сервис записывает фото, предложенный и выбранный ID в `data/identity-reviews/`. Повторное решение для того же файла обновляет разметку. Эти записи хранятся отдельно от эталонов каталога и доступны для последующей подготовки обучающей выборки.

## Каталог из архива заповедника

Чтобы наполнить каталог 15 особями из фотобанка, не распаковывая 15 ГБ:

```bash
npm run catalog:seed -- "/путь/к/przewalski-horses-2026-10-29 (1).zip"
```

Скрипт `ml/seed_catalog.py` читает JPEG прямо из ZIP, сверяет папки особей с номерами паспортов, оставляет до 6 фото на особь с максимальным разбросом дат съёмки (EXIF) и сохраняет эталоны в `data/horses.json` + `data/images/`. Дата съёмки попадает в поле `takenAt`, поэтому каждая карточка показывает период наблюдений, а кнопка «Хронология» открывает ленту взросления особи.

## Части тела и Kaggle-дообучение

Сегментация ушей, ног и тела обучается отдельно на DINOv3 и возвращается одним файлом `data/ml/horse_parts.pt`; без него кнопка «Части тела» честно сообщает, что модель не установлена. Инструмент ручной разметки — `tools/labeler.html`, скрипт обучения с псевдоразметкой и инструкция — в [kaggle/README.md](kaggle/README.md). Число классов распознавания равно числу особей в каталоге и растёт без изменения кода.

## Как работает сравнение

Если установлена MegaDescriptor, сервис использует её визуальные признаки. Обученная часть `data/ml/species_auto.pt` автоматически выбирает один из двух классов: «лошадь Пржевальского» или «другой вид». Второй обученный фильтр `data/ml/species_hard_guard.pt` дополнительно проверяет положительные решения на сходство с ослами и зебрами. При низком качестве кадра интерфейс предупреждает, что ответ менее надёжен, но всё равно выводит решение. Для целевого вида сервис сравнивает целый кадр и его области с фотографиями каталога и автоматически показывает наиболее похожую запись. Проверка вида работает и при пустом каталоге. Модель загружается в память при каждом поиске; на небольшом каталоге это занимает несколько секунд.

Если MegaDescriptor недоступна, на macOS используется системная Apple Vision. Если недоступна и она, остаётся базовый режим с dHash, цветовой гистограммой и сеткой яркости. Интерфейс указывает использованный режим. При поиске с моделью фотография передаётся только локальному серверу и удаляется из временной папки после обработки.

## Обучение

Если размеченный архив кейса ещё скачивается, дождитесь завершения загрузки. После этого можно посмотреть его структуру **без распаковки 15 ГБ**:

```bash
npm run dataset:inspect -- "/путь/к/архиву.zip" --output data/dataset_inventory.json
```

Отчёт перечислит снимки, таблицы, папки и даты в именах файлов. Названия папок не считаются подтверждёнными ID особей: перед обучением нужно сверить их с разметкой. Для проверки по датам съёмки эти даты должны быть в данных, а не только в имени архива.

Для ZIP с фотобанком заповедника запустите `npm run benchmark:reserve -- "/путь/к/архиву.zip"`. Скрипт читает JPEG прямо из архива, берёт метку из папки особи и использует дату съёмки из EXIF. Одна календарная граница разделяет ранние эталоны и более поздние запросы. Результаты по снимкам сохраняются в `data/ml/reserve_identity_report.json`, обученная часть в `data/ml/horse_head_reserve_candidate.pt`. Этот прогон оценивает поиск по каталогу на целых кадрах.

Флаг `--horse-crops` в той же команде оценивает только кадры с одной рамкой YOLO26x. Отчёт с суффиксом `_crops` отдельно показывает кадры без рамки или с несколькими рамками. Разметка привязана к фотографии, поэтому нахождение одной рамки само по себе не подтверждает личность лошади внутри неё.

Найдены [Horse‑30](https://huggingface.co/datasets/mwmathis/Horse-30) с метками домашних лошадей и [фотографии лошадей Пржевальского](https://commons.wikimedia.org/wiki/Category:Equus_przewalskii) без меток особей. Подробности и лицензии — в [DATASETS.md](DATASETS.md). Фотографии Пржевальского скачиваются командой `npm run photos:fetch`; их нельзя использовать для обучения идентификации без подтверждённых идентификаторов.

После распаковки Horse‑30 в `datasets/horse30/` можно запустить `npm run train:horse30`. Скрипт учит небольшую метрическую часть поверх MegaDescriptor и проверяет её на **других лошадях**, которых не было в обучении. Обученная часть включается в поиск только если результат проверки заметно улучшился. Последний отчёт — `data/ml/training_report.json`.

Когда в каталоге появятся минимум четыре подтверждённые особи с пятью разными фотографиями каждой, запустите `npm run train:catalog`. Желательно иметь съёмки в разные дни, при разных ракурсах и фоне. Несколько соседних кадров одной серии не заменяют независимые наблюдения.

**Ограничение:** даже специализированная модель без размеченных фотографий конкретных лошадей Пржевальского не может надёжно назвать особь. Сервис автоматически выбирает ближайшую запись, но её точность пока не измерена. Если правильной особи нет в каталоге, он всё равно назовёт наиболее похожую. Несколько лошадей в кадре делают результат неоднозначным.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/horses` | Каталог без внутренних признаков |
| POST | `/api/horses` | Создать запись с фотографией |
| POST | `/api/horses/:id/photos` | Добавить ракурс |
| POST | `/api/identify` | Получить похожие записи по снимку и признакам |
| DELETE | `/api/horses/:id` | Удалить запись |

Для сохранения фотографии передаются `name`, `notes` и `photo: { dataUrl, features }`. Для поиска передаются `dataUrl` и `features`. В ответе поле `method` равно `megadescriptor`, `trained`, `vision` или `visual`. При работе модели поле `species.decision` равно `przewalski` или `not_przewalski`; `unavailable` означает отсутствие обученной части. `species.lowQuality` отмечает плохое качество кадра. `species.score` относится к первому фильтру; при его положительном ответе `species.guardScore` относится ко второму. Эти оценки не являются калиброванными вероятностями. Поддерживаются JPG, PNG и WebP до 7 МБ.

Обычный `npm start` слушает только `127.0.0.1` и не требует пароля. `npm run share` тоже оставляет локальный сервер на `127.0.0.1`, но требует пароль для страницы, фотографий и API; через туннель каталог доступен только для чтения. Одновременно обрабатываются не более двух запросов распознавания.

## Проверка

```bash
npm test
npm run benchmark:evaluate
npm run benchmark:stress
npm run benchmark:new
npm run train:species-expanded
npm run benchmark:large-evaluate
npm run train:hard-negatives
npm run train:large-audit
npm run benchmark:extra-build
npm run train:extra-audit
npm run benchmark:multiview
npm run benchmark:identity-demo
```

Проверочный набор из 30 целевых и 30 ложных снимков лежит в `datasets/benchmark/`; источники и состав описаны в [DATASETS.md](DATASETS.md), результат — в [BENCHMARK.md](BENCHMARK.md). Его можно пересобрать командой `npm run benchmark:build`. `npm run benchmark:evaluate` обучает фильтр, подбирает строгие пороги по обучающей части, проверяет на отложенной части и сохраняет допущенный фильтр в `data/ml/species_gate.pt`. Отчёт — `data/ml/benchmark_report.json`. На текущей проверке было 0 ошибочных окончательных решений и 11 сомнительных случаев из 30, но выборка мала. Идентификация конкретных особей пока не проверена.

Дополнительные 27 целевых и 30 отрицательных кадров собраны в `datasets/benchmark_new/`; пересборка — `npm run benchmark:expand`. Автоматическая часть ошиблась на 4 из 43 отложенных фото. Подробности и ограничения оценки — в [BENCHMARK.md](BENCHMARK.md).

Ещё 613 фото находятся в `datasets/large_audit/`; сборка — `npm run benchmark:large-build`, расширение до текущего объёма — `npm run benchmark:large-expand`. В наборе 54 целевых фото и 559 отрицательных. Первый фильтр ошибочно принял 3 домашних лошадей, 3 зебр и 11 ослов, а также пропустил 9 целевых снимков. Совместное решение двух фильтров приняло 3 домашних лошадей, 0 зебр и 4 ослов, но пропустило 10 целевых снимков. На 175 снимках, отложенных при обучении второго фильтра, число ошибок изменилось с 14 до 11. Однако для выбора фильтра использовалась эта же отложенная часть, а часть из 613 снимков участвовала в обучении: для независимой оценки нужны новые фото. Кадры домашних лошадей взяты из 20 серий и не являются независимыми наблюдениями. Пробное дообучение как полная замена первого фильтра не прошло проверку; второй используется только для проверки положительных решений. Повторить выбор и подключение можно командами `npm run train:large-audit` и `npm run train:promote-guard`.

Дополнительно в `datasets/extra_audit/` собрано 300 кадров обычных лошадей из десяти других серий Horse‑30. Итого в двух крупных проверочных наборах 913 файлов, но новые 300 кадров не являются независимыми наблюдениями или фотографиями лошадей Пржевальского. Текущая модель верно отклонила все 150 кадров из пяти оставленных серий. Новое дообучение и распознавание по нескольким областям кадра не улучшили общий результат на проверке, поэтому рабочая модель не заменялась. См. [BENCHMARK.md](BENCHMARK.md) и [DATASETS.md](DATASETS.md).

Когда доступ к Wikimedia Commons снова появится, `npm run benchmark:large-expand` попытается собрать до 100 атрибутированных фото лошадей Пржевальского из разных зоопарковых категорий (по доступности и лицензиям). Это отдельная будущая загрузка: текущая коллекция содержит 54 таких фото в `large_audit/`.
